## Open questions (flag — do not guess in implementation)

1. **`httpx2` package availability** — §5.1/§5.2 name `httpx2` ("Pydantic continuation of httpx",
   `import httpx2`, `requires-python >= 3.11`). Confirm this package exists on PyPI with the described
   API (`httpx2.Client`, `httpx2.AsyncClient`, `httpx2.MockTransport`, `files={"xml": (...)}`). If the
   package is unavailable or unpublished, escalate — do NOT silently substitute `httpx`.
2. **Python `cli.py` surface** — §5.3 lists `cli` in the module map and §5.1 says "CLI: typer
   (`dgii-ecf` entry point)", but the spec never enumerates subcommands/flags. The command surface
   (e.g. `dgii-ecf sign`, `dgii-ecf send`, `dgii-ecf auth`) is unspecified. Flag and propose a minimal
   mapping over the client methods before implementing Task 3.13.
3. **Python JSON↔XML transformer** — §5.3 says "Mirror the TypeScript module map 1:1"; the TS
   `transformer.ts` uses `xml-js` for `json2xml`/`xml2json`, but §5.2 lists no JSON↔XML library for
   Python (only `lxml`). Decide whether to implement with lxml directly or add a dependency.
4. **`statusTrackId` endpoint mapping** — `TRACK_RESULT_STATUS` (`consultaresultado`) vs
   `INQUIRY_STATUS` (`consultaestado`) is not explicitly tied to the client methods; the mapping
   `statusTrackId → TRACK_RESULT_STATUS` and `inquiryStatus → INQUIRY_STATUS` is inferred. Confirm
   against the reference implementation before wiring Task 2.12/3.12.
5. **`bun.lock` vs `bun.lockb`** — §4.1 pins `bun@1.4.4` and names `bun.lock`; confirm the lockfile
   name produced by the pinned bun version.
