## 1. Requirements quoted verbatim

### 1.1 Current behavior (quoted)

> `reconcileSubmission` / `reconcile_submission` reports `canReuseSequence: false` for **every** rejected e-NCF, regardless of what DGII answers, because the flag is read from an endpoint whose response does not carry it.
>
> The chain, in both packages:
>
> | Step                                   | TypeScript                                                              | Python                                          |
> | -------------------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------- |
> | reconcile reads the wrong consult      | `packages/typescript/src/client.ts:390` → `this.inquiryStatus(...)`     | `packages/python/src/py_dgii_ecf/client.py:507` |
> | the flag is derived from that response | `client.ts:403` → `canReuseSequence(inquiry.value)`                     | `client.py:520`                                 |
> | the predicate                          | `src/reconciliation.ts:29-31` → `response.secuenciaUtilizada === false` | `src/py_dgii_ecf/reconciliation.py:30-33`       |
> | the endpoint behind `inquiryStatus`    | `src/environment.ts:29` → `consultaestado/api/Consultas/Estado`         | `src/py_dgii_ecf/environment.py:34`             |
>
> `secuenciaUtilizada` is **not** part of DGII's `consultaestado` response. Per DGII's _Descripción Técnica Servicios DGII_ (`project-tasks/124-source-register.md`, row `TEC-02`), the field is published on:
>
> - **`consultaresultado`** (`…/consultaresultado/api/consultas/estado?trackid=`) — the track-result consult, response JSON/XML on p. 23-25 of that document, and its 18-04-2022 bitácora entry states the two parameters were added to _Consulta Resultado_ precisely to tell the caller when an e-NCF may be reused;
> - the **RFCE reception** response;
> - **`consultarfce`**.
>
> `consultaestado` (`RespuestaConsultaEstado`) has no such element. So `inquiry.value.secuenciaUtilizada` is always `undefined`, and `undefined === false` is `false`.
>
> The SDK models the field anyway (`packages/typescript/src/types.ts:44-50` declares it optional on `InquiryStatusResponse`; `packages/python/src/py_dgii_ecf/types.py:264-290` parses it), so nothing fails loudly — the capability is simply dead.

### 1.2 Expected behavior (quoted)

> `canReuseSequence` must reflect DGII's actual answer for the document. DGII sets `secuenciaUtilizada` to `false` for a rejection that leaves the sequence reusable (invalid certificate or signature, invalid XML, non-delegated signer, unauthorized or expired e-NCF, non-electronic issuer, unknown or inactive RNC) — today the SDK can never report that case.
>
> Fiscal impact: an integrator who asks the SDK "can I reuse this sequence?" is always told no, so they burn a new authorized e-NCF where DGII would have allowed reuse. Sequences are authorized ranges, so exhausting them costs a re-authorization cycle.

### 1.3 Steps to reproduce (quoted)

> 1. Reconcile a real rejection whose sequence DGII considers reusable (certificate/signature or XML-structure rejection) against TesteCF.
> 2. Observe `reconcileSubmission(...)` → `canReuseSequence === false`, while `statusTrackId(trackId)` for the same document returns `secuenciaUtilizada: false`.
>
> Or statically: follow `canReuseSequence` back from `reconcileSubmission` to `inquiryStatus` and compare that endpoint's documented response with the field it is read from.

### 1.4 Why the test suite does not catch it (quoted)

> `packages/typescript/test/reconciliation.test.ts:103` asserts `canReuseSequence === true` from a mocked `consultaestado` response containing `secuenciaUtilizada: false` — a response DGII does not produce. Same shape in `packages/python/tests/test_reconciliation.py` (`test_can_reuse_sequence`). The unit tests encode the code path instead of the wire contract, which is the trap `AGENTS.md` already warns about for signing.

### 1.5 Fix direction and its constraints (quoted)

> Resolve the track id first, then read the flag where DGII publishes it:
>
> `trackStatuses(rnc, encf)` (`consultatrackids`) → `statusTrackId(trackId)` (`consultaresultado`) → `secuenciaUtilizada`.
>
> Constraints this fix must respect:
>
> - Both packages in the same change, behaviourally identical (no shared code between them).
> - The conservative `absent flag → not reusable` default can stay, but the _documented_ happy path must become reachable.
> - Do not touch the idempotency ordering (marker persisted before transmit, cleared only on `No encontrado`), the retry predicate, or `delivered`/`cleared` semantics.
> - If the extra round trip is unacceptable, the alternative is to stop exposing `canReuseSequence` as a capability — but then `docs/*/guides/resilience.md` must stop describing it as the way to decide reuse.

### 1.6 Provenance (quoted)

Provenance evidence: `project-tasks/124-source-register.md` (rows `TEC-02`, `TEC-01`; mapping steps 6-7) and `project-tasks/124-evidence/t1-refuter-register.md` (Finding 1).

## 3. Decisions and constraints (record; do not re-litigate in implementation)

1. **The contract is P1's, not the implementer's.** No source line changes before `project-tasks/126-contract-design.md` is frozen PASS by both validators (contract C-1). If it changes later, T2 and T3 re-run and T4/T5 are notified.
2. **The fix reuses existing public methods.** `trackStatuses`/`statusTrackId` (and Python twins) already exist. No new public method, no new option, no new module. A field on `ReconciliationResult` is **not** part of the issue's ask — default is "no new field"; T1 must justify with the issue text if it wants one, and the repo owner signs off.
3. **The exported predicates may keep their shape.** TS `canReuseSequence` takes a structural `{ secuenciaUtilizada?: boolean | null }` and a track response is assignable to it, so it can stay unchanged. Python's `can_reuse_sequence` is annotated to `InquiryStatusResponse`; the frozen design states whether it widens (union/protocol) or is re-annotated, and `project-docs/architecture.md` records the answer. A breaking re-annotation is allowed only with a PR-body call-out.
4. **Ordering is fixed by the issue and by `AGENTS.md`.** `inquiryStatus` still runs first and still decides `delivered` / `cleared` and the marker delete. The new calls run **after** that decision and cannot influence it. Reconcile never writes a marker (it is a query method, not idempotency-keyed — `architecture.md` §9.3).
5. **Precedence for every non-`false` value is `not reusable`.** `undefined`, `null`, missing track list, missing `trackId`, and any non-boolean value all answer `false`. Only a literal `false` on the wire makes `canReuseSequence` true (R8).
6. **The tests must mock the wire, not the code path.** Each mocked payload must be shaped like the TEC-02 response for that endpoint, and the test must assert the URL/request sequence. A test that can pass against `consultaestado` carrying the flag is a FAIL (this is the exact trap R5 records).
7. **Failure disposition is one decision, identical in both packages**, recorded in C-1 before implementation: either propagate the `Err` from the new calls or answer `Ok` with `canReuseSequence: false`. Whatever is chosen, the caller must not lose a `cleared: true` decision that already happened, and no exception may escape (`AGENTS.md`: results, not exceptions).
8. **Document types beyond the plain e-CF are a design question, not scope.** `reconcileSubmission` can be handed an RFCE summary, whose flag lives on the RFCE reception response / `consultarfce` (PROD-only). T1 states the behaviour with citations; where the chain does not apply, the conservative `false` of Decision 5 governs. No new API may be added for it.
9. **Two locales or neither.** `docs/en` and `docs/es` are diffed by CI; a site-docs task touches both in the same commit, with the same structure.
10. **`uv` runs use `--frozen`.** A plain `uv run` can rewrite `uv.lock` as a side effect (`AGENTS.md`). CI runs `uv lock --check`.
11. **One owner per file.** TS source/tests → T4. Python source/tests → T5. `project-docs/architecture.md` → T8. `docs/**` → T9. No two tasks edit the same file.
12. **No scope beyond the issue.** No new endpoint constant, no RFCE-specific reconcile, no CLI command, no example update, no signing change, no version bump.
