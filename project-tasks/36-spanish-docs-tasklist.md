## 1. Issue summary (quoted)

**Goal:** the docs site (`mkdocs.yml`, `docs/`) and the examples' READMEs are currently English-only. Add a Spanish (`es`) version of the documentation and examples and serve them as a **multilingual** site from GitHub Pages.

**Issue-mandated approach:**

> - Use [`mkdocs-static-i18n`](https://github.com/ultrabug/mkdocs-static-i18n) (works with the Material theme and `mkdocs build --strict`).
> - Configure `mkdocs.yml` with `plugins: [i18n]` and `i18n` config:
>   - `docs_structure: folder` (e.g. `docs/es/...`) or `suffix` (`page.es.md`).
>   - `default_language: en`, `languages: [en, es]`.
> - Add a **language switcher** to the Material theme.
> - Translate every nav page (`index`, `installation`, `typescript`, `python`, `guides/*`, `examples`, `faq`).
> - Add Spanish READMEs for `examples/python` and `examples/typescript` (and translate the user-facing strings in the example scripts).
> - Keep **code, comments, and commit messages in English** (repo convention); translate user-facing docs.

**Issue acceptance criteria — verbatim:**

- [x] `mkdocs build --strict` succeeds with `en` + `es`.
- [x] A language switcher is visible and works on every page.
- [x] All nav pages have a Spanish translation (no missing/empty pages).
- [x] `examples/python/README.md` and `examples/typescript/README.md` have Spanish versions.
- [ ] GitHub Pages serves both languages at `https://deuriib.github.io/dgii-ecf/` and `https://deuriib.github.io/dgii-ecf/es/`.
- [x] Docs workflow stays green.

**Issue notes (quoted):**

> - Consider setting `site_url` and the `i18n` fallback correctly so `--strict` doesn't flag missing translations during the transition.
> - If a page is not yet translated, the plugin can fall back to English; track the remaining pages in a checklist.

## 3. Decisions and constraints (record these; do not re-litigate in implementation)

1. **`docs_structure: folder`** (as suggested by the issue) — this requires moving **all** English pages into `docs/en/`. Do it with `git mv` so history follows the files. URLs are unaffected for English (default locale builds at the site root) and Spanish builds at `/es/`.
2. **`fallback_to_default: true`** keeps `--strict` green while pages are being translated. Fallbacks are a safety net, **not** the deliverable: acceptance criterion 3 requires real Spanish files, so each translation task must add the actual file, never rely on a fallback.
3. **The language switcher is generated by the plugin** (`reconfigure_material: true` is the default). It auto-creates `extra.alternate` with **contextual, same-page** links. Do **not** hand-write `extra.alternate` in `mkdocs.yml` — a manual block duplicates/overrides the generated switcher. Verify the rendered switcher instead; only add explicit `extra.alternate` if the generated links are wrong, and then keep it in sync with `site_url`.
4. **`navigation.instant` must stay off** — the plugin documents it as incompatible with the multi-language switcher. It is not enabled today; do not enable it.
5. **`site_url` must stay `https://deuriib.github.io/dgii-ecf/`** (trailing slash included) — the switcher and `sitemap.xml` use it to build absolute alternate links.
6. **Translation boundary:** translate prose, Markdown headings, table headers/cells that are prose, admonition **titles**, and link text. **Do not change**: code blocks, inline code, shell commands, file names, identifiers, API names, env vars, URLs, badges, `!!! note`/`!!! warning` keywords, `=== "TypeScript"` tab labels, or comments inside code. Technical terms stay as-is: `e-CF`, `e-NCF`, `RFCE`, `ACECF`, `ANECF`, `XMLDSig`, `C14N`, `RSA-SHA256`, `P12`, `SEED`, `track id`, `Result`, `circuit breaker`.
7. **Spanish style:** neutral Latin-American Spanish, second person singular (`tú`), present tense, imperative for instructions. No regionalisms, no machine-translation artifacts, no leftover English sentences outside the boundary above.
8. **No stubs:** no `TODO`, no "translation pending", no empty pages, no `.es.md` suffix files (we use `folder`). Every `docs/es/**` page must be a complete translation of its `docs/en/**` counterpart.
9. **Language:** code, comments, file names, and commits in English (repo convention). The Spanish READMEs and the `docs/es/**` pages are the only Spanish artifacts.
10. **Out of scope:** theme change, new languages, nav restructuring, new pages, new MkDocs extensions, changes to packages, changes to `examples/*/*.ts|*.py` source.

### Gap flagged against the issue body

The issue's _Task_ section says "translate the user-facing strings in the example scripts", but its **acceptance criteria** only require Spanish READMEs. Translating `console.log`/`print` output would change program output (code, not docs) and conflicts with "keep code in English". **Decision: do not touch example script strings.** The Spanish READMEs explain the flows in Spanish; commands and outputs stay English. If the issue author wants localized console output later, that is a separate issue.

## 7. Risks and gotchas (do not rediscover these)

1. **`folder` structure moves all English pages.** Use `git mv`; if you copy+delete, `git log --follow` history breaks. `edit_uri: edit/main/docs/` keeps working because page `src_path` becomes `en/index.md` — verify the "Edit this page" link resolves to `docs/en/...`, and to `docs/es/...` on Spanish pages. If it resolves to the wrong path, fix `edit_uri`, do not restructure the docs.
2. **Do not hand-write `extra.alternate`.** `reconfigure_material: true` generates the switcher with contextual links. A manual block will duplicate entries or point both languages at the root.
3. **`--strict` + fallback can mask a missing translation.** With `fallback_to_default: true`, a missing `docs/es/faq.md` builds green by serving English at `/es/faq.html`. The page-parity diff in the final gate is the real check — never trust a green build alone for acceptance criterion 3.
4. **`navigation.instant` is incompatible** with the switcher. Do not add it, do not add `navigation.instant.progress`.
5. **`theme.language: en` stays as the base value.** The plugin overrides `lang` per locale; if Spanish pages render `<html lang="en">`, `reconfigure_material` was disabled — re-enable it instead of hardcoding a second theme block.
6. **`mkdocs-static-i18n` is frozen upstream** (MkDocs 2.0 uncertainty, per the plugin README). The issue mandates it, so use it, but pin the resolved version in the PR description (e.g. record the exact `mkdocs-static-i18n` version uvx resolved) so CI is reproducible if a later release breaks `--strict`.
7. **Search duplication:** `reconfigure_search: true` (default) dedupes fallback copies. Leave it on, and keep `- search` listed before `- i18n`.
8. **Do not translate the English pages.** Every task's check includes `git diff --quiet` on the corresponding `docs/en/**` file; the English tree is frozen after Task 1.
9. **No server, no background process.** All verification is `mkdocs build` into the gitignored `site/`; do not run `mkdocs serve` in CI or in the agent session.
10. **README language links must be relative** (`README.es.md`), not absolute GitHub URLs, so they work in forks and in the GitHub UI.
