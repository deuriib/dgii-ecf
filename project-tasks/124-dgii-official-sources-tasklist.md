## 1. Requirements quoted verbatim

### 1.1 Context (quoted, non-normative — orientation only, no acceptance ID)

> The published mkdocs guides (`docs/en/guides/*`, mirrored in `docs/es`) describe each e-CF step —
> authenticate, pre-flight, routing, sign, submit, track, reconcile — but they cite only one blanket
> pointer to `project-docs/dgii-ground-truth.md`, which is **not published on the site**. A reader who
> needs to verify a step against the regulator's rules (norms, technical specification, manuals,
> Ley 32-23, Decreto 587-24) has to leave the docs and dig through the repo. Integration teams and
> auditors hit this constantly.

### 1.2 Repro / Proposal (quoted verbatim)

> Task — make the official DGII provenance visible per step in the docs site:
>
> - Add an **Official DGII References** page to mkdocs (e.g. `docs/en/reference/dgii-official.md` +
>   `docs/es` mirror) cataloging the official documents behind `project-docs/dgii-ground-truth.md`
>   (the 34 sources): title, version/date, canonical DGII URL.
> - In each numbered step of `guides/flow.md`, add an inline "Official source" line linking to the
>   specific DGII document/section that governs that step (e.g. seed validation → e-CF technical
>   spec, authentication section; signing → XMLDSig/standardization rules; reception endpoints →
>   per-service spec for `ecf.dgii.gov.do` vs `fc.dgii.gov.do`).
> - Same treatment for `guides/signing.md` (W3C XMLDSig/C14N refs already present — add the DGII
>   normative doc on top) and `guides/resilience.md` (idempotency/sequence rules per the norm).
> - Keep `project-docs/dgii-ground-truth.md` as the internal source of truth; the site pages link
>   into DGII's published docs, not into repo files, so the public site is self-contained.
> - **Non-goals:** do not mirror, scrape, or rehost DGII document content into the site; no SDK code
>   changes; no translation of DGII PDFs.

## 3. Decisions and constraints (record these; do not re-litigate in implementation)

1. **The citation set is not invented here.** Every title, version/date, URL, section name and access date comes from `project-tasks/124-source-register.md`. A writer who cannot find a document in the register does not add it — the task fails back to T1.
2. **The "34 sources" count.** The repository has no enumeration of those 34 documents (`project-docs/dgii-ground-truth.md` names its NotebookLM notebook but lists no titles or URLs, and DGII folder listings return `401`). Standing human decision (deuriib, 2026-02-14): publish the **verified** count with an explicit note that the internal audit drew on 34 sources; never pad to 34, never invent an entry.
3. **Self-containment (R4).** The site must not link to `project-docs/**` or to any `github.com/deuriib/dgii-ecf/blob/...` path. The one existing blanket pointer (`flow.md:7`, both locales) is therefore replaced by a link to the new reference page — that is the minimum R4 requires; no other page is touched.
4. **"Official source" line placement is deterministic.** In `guides/flow.md` the line is the **first paragraph after each `## N.` heading** (prettier inserts the blank line). That makes A3 machine-checkable instead of eyeballed.
5. **Line format (identical shape in both locales; only the label and the section wording are translated):**
   - EN — `**Official source:** [<DGII document title>](<URL>) — <section / article>, accessed <YYYY-MM-DD>.`
   - ES — `**Fuente oficial:** [<DGII document title>](<URL>) — <sección / artículo>, consultado <YYYY-MM-DD>.`
   - The document title stays in its published Spanish wording in both locales (it is a proper name, not prose). The URL must be **byte-identical across locales**.
6. **Scope of "every numbered step" = the 7 numbered steps.** `Auxiliary flows` and `Common mistakes` are not numbered steps and get **no** citation lines (journal: the run ledger's P2 mentions aux flows; the issue scopes "each numbered step" and A3 measures numbered steps — the issue wins).
7. **Nav shape (A2).** Exactly **one** new top-level nav label, placed after the `Guides` block, plus **one** `nav_translations` key. Introducing a new `Reference:` parent section would create a second untranslated key — out of scope.
8. **Link rot is expected.** DGII URLs move and reject non-browser clients. Access dates are mandatory on the reference page, and every external URL needs link evidence (T11). A dead link blocks the task; a "known to move" URL keeps its access date and is flagged in the maintenance note.
9. **Translation boundary.** Translate prose, headings, table headers/cells that are prose, and the "Official source" label. Do **not** change: code blocks, inline code, identifiers, API names, URLs, `=== "TypeScript"` / `=== "Python"` tab labels, admonition types, or document titles. Keep technical terms verbatim: `e-CF`, `e-NCF`, `RFCE`, `ACECF`, `ANECF`, `XMLDSig`, `C14N`, `RSA-SHA256`, `.p12`, `trackId`, `secuenciaUtilizada`.
10. **Language.** All prose for the English tree is English; repository language for commits/task artifacts is English. Spanish exists only inside `docs/es/**`.
11. **One owner per file.** `mkdocs.yml` belongs to T10 alone. No two tasks edit the same file. `project-docs/dgii-ground-truth.md` is **read-only** input, never edited.
