## 3. Decisions & Technical Constraints

1. **Dual Invocation Pattern**:
   - **TypeScript**: Methods are exposed both statically on `Transformer` and on instances (`new Transformer()`). Instance methods delegate to static methods (or share implementation) so `Transformer.json2xml(...)` and `new Transformer().json2xml(...)` behave identically.
   - **Python**: Using `@staticmethod` on `Transformer` cleanly supports both `Transformer.json_to_xml(...)` and `Transformer().json_to_xml(...)` out-of-the-box according to Python's descriptor protocol.
2. **Error Handling & Code Normalization**:
   - Results, not exceptions: Return `Result<string, DgiiError>` (`neverthrow`) in TS, `DgiiResult[str]` (`result`) in Python.
   - Any JSON parse failure (e.g., malformed JSON syntax) or non-object root (e.g., JSON null, boolean, primitive number, or array) MUST yield a `DgiiError` with code `INVALID_XML` (`DgiiErrorCode.INVALID_XML`).
3. **Strict Typing**:
   - TS: strict mode, no `any`, use `unknown` / `object` / `string` with proper narrowing.
   - Python: `mypy --strict` + `disallow_any_explicit` (no `Any`). Type data as `Mapping[str, object] | str` or `dict[str, object] | str`.
4. **Naming Parity Matrix**:
   - TypeScript: Canonical `json2xml` / `xml2json`, with aliases `json_to_xml`, `jsonToXml`, `xml_to_json`, `xmlToJson`.
   - Python: Canonical `json_to_xml` / `xml_to_json`, with aliases `json2xml`, `xml2json`.
5. **Python CLI Contract**:
   - Subcommand: `py-dgii-ecf json-to-xml <json_file> [--output <output.xml>] [--round-monetary]`.
   - On error: print `error: <message>` to `stderr` and exit with code `1`.
   - On success: write to `--output` file if specified (and print `xml document written to <output>`), else print XML to `stdout`.
6. **Documentation & Parity Upkeep**:
   - Any updates to `project-docs/architecture.md` must accurately reflect exported TypeScript and Python interfaces.
   - Any user-facing docs updates must follow the two-locale rule (`docs/en/` and `docs/es/` kept identical).
