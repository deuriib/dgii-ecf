# Official DGII references

Both SDKs in this repository implement the rules that the **Dirección General de
Impuestos Internos (DGII)** publishes for electronic fiscal receipts (e-CF). This
page is the index of those rules: it names the DGII document that governs each
part of the integration and links to DGII's own published copy of it.

DGII republishes files in place — the URL stays the same while the file's content
changes, and a version bump is not guaranteed. Every row below therefore records
the version together with the publication date DGII shows for the file, so a
later change is visible.

**Access date for every row: 2026-11-09.**

!!! note "How to read this page"

    Links go to the documents DGII publishes — and, for the signature standard,
    to the W3C and IETF specifications that DGII's signing profile normatively
    references. Nothing from those documents is reproduced here: titles,
    versions, one-line attributions and links only.

## Signature and XML standards

The specifications behind the e-CF signature profile. DGII's _Firmado
Comprobantes Fiscales Electrónicos_ names them; the algorithm URIs in the
signature are their vocabulary.

| Document                                | Version / date     | What it governs                                                                      | Official link                                           |
| --------------------------------------- | ------------------ | ------------------------------------------------------------------------------------ | ------------------------------------------------------- |
| XML Signature Syntax and Processing 1.1 | W3C Recommendation | The enveloped-signature transform, `SignedInfo`, `Reference`, `KeyInfo`/`X509Data`   | [W3C](https://www.w3.org/TR/xmldsig-core1/)             |
| Canonical XML 1.0                       | W3C Recommendation | Inclusive C14N, comments removed                                                     | [W3C](https://www.w3.org/TR/2001/REC-xml-c14n-20010315) |
| XML Encryption 1.1                      | W3C Recommendation | The `…/2001/04/xmlenc#sha256` digest algorithm URI                                   | [W3C](https://www.w3.org/TR/xmlenc-core1/)              |
| RFC 6931                                | RFC 6931 (IETF)    | Registers the `…/2001/04/xmldsig-more#rsa-sha256` URI (RSA PKCS#1 v1.5 with SHA-256) | [RFC](https://www.rfc-editor.org/rfc/rfc6931)           |

RFC 6931 is IETF rather than W3C because the `xmldsig-more` algorithm URI has no
W3C recommendation of its own: the RFC is its normative registry entry, not a
mirror of one.

!!! warning "A type exclusion for B2B is the SDK's rule, not DGII's"

    DGII's published documents state no list of e-CF types excluded from the
    direct issuer↔receiver flow. The SDK applies its own guard
    (`enforceB2BRules` / `enforce_b2b_rules`, on by default) and declines to
    deliver E32 below RD$250,000, E41, E43, E45, E46 and E47 straight to a buyer.
    Treat that as an SDK rule: it keeps a delivery from failing at the buyer, but
    it is not a cited DGII requirement.

## Scope of this page

The SDKs' internal normative reference was assembled from 34 sources; this page
is not that list and does not claim to be. What is published here is each
document that a step or a field on this site depends on, together with the
certification and contingency material those steps send readers to, verified
reachable on the access date, with the URL and the version each one was checked
at, so anyone can re-check them. DGII publishes more than this: documents that
nothing here depends on are not listed.

DGII publishes no machine-readable definition of the five e-CF web services and
no public certification test-case set, so neither is cited here: the service
shapes come from the technical description.
